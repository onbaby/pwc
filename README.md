# Right on Time

Demo prototype for the UGA AI Society × PwC case competition (Classic Cup Coffee). A text-message system that estimates how much coffee each online subscriber has left, proposes a better delivery date with an honest range, lets the subscriber confirm by text, and is judged in a pre-written pilot that can be stopped.

**Everything on screen is synthetic or from public data. No client data. Nothing here is a forecast.** The full requirements are in [PROTOTYPE_SPEC.md](PROTOTYPE_SPEC.md).

## Run it

```bash
nvm use            # Node 24 (.nvmrc)
pnpm install
pnpm demo CHANNEL=replay     # or: CHANNEL=replay pnpm demo
```

`pnpm demo` builds the web app and serves everything on one port (default http://localhost:8787). It **refuses to start without an explicit channel**:

| Channel | What it does | Needs |
|---|---|---|
| `replay` | Scripted customer texts drive the real engine on the step key. Always works. | nothing |
| `console` | You type as the customer (phone-mock input box or stdin). | nothing |
| `photon` | Real iMessage on team phones via Photon Spectrum; falls back to replay if it has not connected in 5 s. | `.env` (see below) |
| `sms-stub` | Twilio-shaped stub, prints the payload it would send. Not used in the demo. | nothing |

`NO_NETWORK=1` makes every `fetch` throw (the demo still runs; photon is refused).

### Presenter controls
`→` / `←` or PageDown / PageUp: next / previous step · `Ctrl+Alt+R`: toggle Replay ↔ Console (from Live: to Replay) · `Ctrl+Alt+B`: backup index · `Ctrl+Alt+0`: reset · in backup: `1`–`8` jump to a tile, `Esc` back. Plain keys never trigger controls while an input is focused. The top-right pills show the mode (LIVE iMessage / REPLAY / CONSOLE), the parser (`RULES`) and `SIMULATED: not a forecast`.

## What the numbers say (so nobody is surprised on stage)

- At the placeholder (40 of every 100 cancellations caused by too much coffee) **Paced does not pay by itself**: about −$12K a year at cohort scale on the strict shipped view. It breaks even only if roughly 95 of every 100 cancellations are stockpile-driven. Even **perfect knowledge of the pantry** needs about 54 of 100. The screen shows required vs delivered vs ceiling, with the red state visible from the start, and the pilot measures the one unknown.
- Paced cuts stockpiles only modestly (about 52 → 47 per 100 deliveries) and is about as late as Fixed; what it adds over a simple rule is mostly calibrated uncertainty and on-time reliability, not a big dollar gain (backup tile 7).
- Real-data check (Online Retail II, 75,281 test predictions): beats a *calibrated* last-gap baseline at every reorder count with the 95% interval below zero; its 80% ranges cover 75.0–78.5% at reorders 1–4. The written rule passed, but coverage at reorder 2 is **75.0%, exactly at the edge of the allowed ±5 points**. Say that if asked.

## Deviations from the spec (on purpose, all documented in code)

1. **Break-even bar** (`packages/core/src/sim/breakeven.ts`): "Required" includes the $2 program cost (the profit line is net of it) and scales only the hazard from day 90 on, because nothing moves before a subscriber's second delivery. The literal spec version made the bars say "pays" while the profit line said "loses". Both the before-cost and net numbers are in the artifact.
2. **φ grid** has 11 points (every 0.1) instead of 6; every spec point is included. The slider interpolates.
3. **Ceiling** targets the latest weekly ship day that is not late (run-out − 1.5 days), with the same ±14-day and [21, 84]-day rules as Paced.
4. **Screen 2 histogram** counts arrivals "if nobody cancelled"; the grid's profit and share metrics are survival-weighted.
5. **Reply wording**: the on-screen explanation says "Maya's own evidence" rather than a pronoun.
6. The expedite offer is **not credited** in the simulator (late rates are conservative).

## What is NOT done / not verified

- **Photon live path is written but untested** (no credentials here). The M1 go/no-go test on two team phones (spec §7.2) still has to be run; if the first agent-initiated message to a fresh phone fails, switch S1 to "Maya texts HELLO first".
- **LLM free-text fallback is not built** (spec stretch goal, default off). The parser is rules only; the pill always shows `RULES`.
- Not built or not done: the rough/final screen recordings, the three timed dry runs under 6:30, the 8-field data-request slide, counsel review of consent and quiet hours.
- The simulator's calibration to Exhibit C is exact by construction; it is a code check, not validation. Every other parameter is a labelled assumption (`docs/assumptions.md`).

## What you need to provide (all optional for the replay demo)

- Photon Spectrum project credentials `SPECTRUM_PROJECT_ID`, `SPECTRUM_PROJECT_SECRET` and opted-in team phones `PERSONA_MAYA_PHONE` etc. in `.env` (copy `.env.example`). Never commit `.env`.
- An Anthropic API key and pinned model id only if you decide to build the LLM fallback.
